# ORDERED·FREE Test Run 두 개 생성

버전 1.0에 생성했다. 생성 시점의 TC 20개는 모두 READY였다. 시나리오는 검토 대기 DRAFT로 저장했으며 QA는 실행하지 않았다.

| Test Run | 실행 방식 | 시나리오 | 서로 다른 TC |
| --- | --- | ---: | ---: |
| [순서 있는 핵심 플레이](https://home.stage.artel.kr/projects/54/test-runs/164) (`TR-9401PM`) | ORDERED | 5 | 20 |
| [순서 없는 핵심 기능](https://home.stage.artel.kr/projects/54/test-runs/165) (`TR-MEPSKT`) | FREE | 1 | 20 |

순서 있는 Test Run:

1. Normal 전투부터 사망과 재도전까지: 메뉴·모드 진입부터 이동, 발사, 전환, 부분·빈 탄창 재장전, 수류탄, 회복, 처치, 정지·해제, 피격·사망·재도전까지 29단계.
2. Zombie 모드 진입: Play와 Zombie 선택 2단계.
3. 상자에서 멀리 떨어진 재장전 제한: 메뉴·Normal 진입과 조건 준비 후 예외 검증 4단계.
4. 최대 체력에서 메디킷 보존: 메뉴·Normal 진입과 조건 준비 후 예외 검증 4단계.
5. 메디킷 원거리 사용 제한: 메뉴·Normal 진입과 조건 준비 후 예외 검증 4단계.

FREE 시나리오는 TC당 한 단계씩 20단계다. 연결 단계 없이 각 TC의 사전조건을 준비하고 실행 순서는 에이전트가 선택한다. 두 Test Run 모두 TC 20개를 포함하지만 실행 경로가 다르다.

무적 치트는 전투 준비에 사용할 수 있다. 피격·사망 검증 전에는 반드시 끄도록 순서형 시나리오에 명시했다. 입력 검증은 실제 키·마우스 입력으로 수행하며 반복 사격 기능으로 대체하지 않는다.

탄약 상자·메디킷에 접근하는 준비 단계는 `teleport_to_target(target, distance=2)`로 변경했다. 호출 결과와 실제 거리가 2m 이내인지 확인한 뒤 재장전·회복 입력을 검사한다. 배치할 빈 공간이 없으면 치트가 실패하므로 조건을 충족한 것처럼 진행하지 않는다. 이 변경으로 Normal 여정과 최대 체력 메디킷 시나리오를 다시 승인 대기로 저장했다. TC-003의 W 이동 입력은 변경하지 않았다. 현재 변경된 두 시나리오의 조회 결과는 `teleport-scenario-result.json`에 있다.

저장 후 단건 조회로 모든 시나리오의 실행 모드, 검토 상태, 단계 수와 TC 순서를 비교했다. 두 Test Run이 각각 20개 TC를 포함하고 FREE의 모든 단계에 case_id가 있는지 확인했다. 서버가 재장전 단계에 덧붙인 조건 문구는 저장 결과에 보존했다. GAP·미상 단계는 없었지만 실제 게임에서의 실행 가능성·판정은 확인하지 않았다.
