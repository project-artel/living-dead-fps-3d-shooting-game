## 공통 실행·판정 기준

각 TC는 독립 실행한다. 전투 TC의 기본 대상은 Normal 모드이며 Zombie가 대상일 때 명시한다. 준비를 다른 TC의 성공에 의존하지 않는다. 게임의 실제 버튼과 객체는 현재 화면에서 식별한다. 없는 selector를 만들어 사용하지 않는다.

새 프로젝트의 2026-11-13 개발 빌드에서 준비 기능 `start_mode`, `set_magazine_ammo`, `set_player_health`와 동작 기능 `aim_at_enemy`, `aim_at_nearest_enemy`, `fire_and_reload`, `move_to_target`의 등록을 확인했다. 인스턴스 `119`의 서버 연결 및 기능 목록 수신을 확인했다. 기능 호출 성공은 확인하지 않았다. 준비 기능은 시작 조건에만 사용한다. 모드 선택 자체의 시험에는 `start_mode`를, 발사 입력 시험에는 `fire_and_reload`를 대체 사용하지 않는다. 준비가 불가능하면 BLOCKED로 기록한다.

입력 전달, 입력 전후 화면, 동일 대상의 관찰값과 준비 기능 사용 여부를 기록한다. 메모리 값은 대상 빌드에서 실제 반환되는 경우에만 보조 증거로 사용한다. 읽기 전용 등록 함수는 현재 0개다. 필드가 소스에 존재하는 것만으로 관찰 가능하다고 가정하지 않는다. 정확한 숫자 판정에 필요한 HUD/메모리 값을 읽을 수 없으면 BLOCKED로 기록한다.

전투 준비에서 로더 완료와 HUD 표시를 확인한다. 로더는 코드상 프레임마다 진행하므로 짧은 고정 대기만으로 실패시키지 않는다. 60초 안에 완료되지 않으면 로더 진행·오류를 기록하고 준비 실패를 구분한다. 사격·재장전·무기 전환은 커서 잠금과 이전 동작 완료를 확인한 뒤 입력한다. 전투 도중 다른 적의 피해나 다른 원인의 처치가 개입하면 해당 비교는 무효다.

예외 TC의 상태 불변은 입력이 게임에 전달됐다는 증거와 함께 판정한다. 입력 도구의 성공 응답이나 상태 불변만으로 거부 동작을 통과시키지 않는다. 동일 입력의 정상 동작 비교는 보조 증거이며 실패한 시도의 입력 수신 증거를 대신하지 않는다.

| 정확한 헤드샷·몸통 피해 비교 | Deferred | 실제 탄착 부위와 대상별 단발 피해를 귀속할 증거가 없다. 적 체력 회복도 비교에 개입한다. |
| 총구·피격 이펙트, 수류탄 비행 모양 | Deferred / 수동 확인 | 짧은 순간의 화면 포착에 의존한다. 지속되는 재고 감소가 이펙트 검증을 대신하지 않는다. |
| Zombie 사망·재도전, 소진 아이템 재사용, 점프·달리기·조준·시간 배속 등 | 추가 범위 | 20개 대표 흐름에서 제외했다. 해당 경로가 검증됐다는 의미는 아니다. |

결함 후보: `player_health.TakeDamage`는 호출 시작 시 `health>0`이면 피해만 빼고, 호출 시작 시 이미 `health<=0`일 때 사망 coroutine을 시작한다. 따라서 치명타 한 번 후 추가 피격이 없으면 Game Over로 진행하지 않을 수 있다. TC-16의 사망 전환 기대값을 이 코드에 맞춰 약화하지 않는다. 게임 코드는 수정하지 않았다.
